# 《拉丝 · 甩上去》Three.js 技术方案 v1

> 目标机：PC（Windows / Linux mini PC）· 43" 屏 · 1080p / 60fps
> 交付：Electron + Chromium kiosk，离线运行
> 视觉：雷曼的层次 + 皮克斯的光

---

## 1. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 渲染 | **Three.js（WebGL2）** | 透视相机、真实灯光、后处理，2.5D 的最短路径 |
| 构建 | Vite + TypeScript | 热更新、类型安全、打包小 |
| 后处理 | EffectComposer | Bloom / DOF / LUT / 输出，官方链路 |
| 动画 | Spine 4.2 + spine-threejs | 网格 + IK；有风险，见 §4 |
| 物理 | 自研固定步长 + XPBD 绳 | 手感可控、可复现，不用通用引擎 |
| 音频 | Web Audio（Howler 可选） | 分层、低延迟 |
| 外壳 | **Electron** | 保证 Chromium 一致，避免 WebView 差异 |
| 调试 | lil-gui + 远程配置 JSON | 现场调参数不用改包 |

## 2. 场景结构：一个"玩具剧场"

```
透视相机 FOV 32°，位于 z = 1000
  z = -1400   远景（雾化 + 预模糊）
  z = -900    中景货架（半虚）
  z = -400    玩法背景
  z = 0       玩法层：角色、绳子、平台、机关
  z = +350    前景遮挡（更暗、预模糊）
```

- 相机只做**轻微推拉 + 纵向跟随**，四层自然产生视差。
- 透视相机（不是正交）是"玩具感"的来源：近大远小。
- 每层用 `MeshBasicMaterial`（自发光贴图）+ 少量受光材质，控制成本。

## 3. 渲染管线（顺序固定）

```
场景 → HDR HalfFloat RenderTarget
     → Bloom（threshold 0.85，只让灯和史莱姆发光）
     → DOF（焦点 z=0，最大模糊 6px）
     → LUT 调色（每区一张）
     → 暗角 + 轻微颗粒
     → ACES Tone Mapping → sRGB
```

**HDR + ACES 是性价比最高的一步**：同一场景，加与不加是两个世代。LUT 每区一张（前厅紫、后厨暖、夜光青）。

## 4. 角色

**主路径**：Spine 4.2 出网格 + IK → `spine-threejs` 渲染 → **自定义 ShaderMaterial**：

- 基础色贴图
- 边缘光（Fresnel，颜色跟随环境灯）
- 镜面高光（湿感）
- 次表面近似（wrap lighting + 边缘透光）
- 张力/情绪驱动的自发光

**已知风险**：spine-threejs 版本较冷门，自定义材质需要改它的 `SkeletonMesh`。
**备选**：把 6 个 clip 烘焙成 60fps 图集，用普通平面 + 自定义材质 —— 可控性更高，内存更大，失去实时 IK。

> 先用主路径做 spike；跑不通再切备选，不要两条同时做。

## 5. 绳子（第二主角）

- 不是 `Line`，是**带法线的网格带**，每帧按两端的距离重建
- 张力 → 宽度变细、自发光增强、高频抖动
- 甩出时加拖影和速度线
- 视觉参数全部暴露在调试面板

## 6. 物理与手感

- **固定步长 120Hz** 子步进，渲染插值；绝不随帧率变
- 两个刚体 + XPBD 距离约束（最大拉伸 1.35×、阻尼、回弹）
- 碰撞：AABB + 斜坡，不用通用物理引擎
- 输入到画面 **≤ 50ms**（硬指标）
- 动画、相机、物理解耦：物理定位，相机滞后，动画叠二次运动

## 7. 素材管线

| 资产 | 要求 |
|---|---|
| 背景 | 每区 4 层 PNG（远景预模糊）；关键道具带法线 |
| 角色 | Spine 工程 + 图集 + 身体法线贴图 |
| 绳子 | 可平铺黏液法线 + 自发光 |
| 调色 | 每区 16³ LUT PNG |
| 粒子 | 统一图集，ADD 混合 |

## 8. 性能预算

| 项 | 目标 |
|---|---|
| 分辨率 | 1080p 渲染（4K 屏可 1440p 上采样） |
| 帧率 | 60fps 锁 |
| Draw call | < 100 |
| 实时光 | ≤ 4 盏 |
| 后处理 | ≤ 5 pass |
| 内存 | < 1GB |
| 冷启动 | < 10s |

## 9. Kiosk（Electron）

- 开机自启、全屏、隐藏光标、禁用 DevTools
- 看门狗：渲染卡死 / 上下文丢失自动重启
- 离线资源 + 远程配置（物理参数、LUT、关卡数据）
- 本地日志 + 每日上报

## 10. Spike（go / no-go）

**范围**：一个区（前厅）、一个角色、一根绳、一条沟、3 盏灯、bloom + DOF + LUT。

**验收**：

1. 43" 屏、真实观看距离下，眯眼能看出"该看哪"
2. 甩出去的手感成立（拉、松、飞、落地）
3. 目标 PC 上稳定 60fps，输入延迟 ≤ 50ms
4. 一帧截图，能放进作品集不丢人

**不过，不铺关卡。**

## 11. 风险

| 风险 | 等级 | 对策 |
|---|---|---|
| spine-threejs 自定义材质难改 | 高 | spike 第一周就验证；备选烘焙图集 |
| 目标 PC 的 GPU/驱动差异 | 中 | 在真机上测；准备降级档（关 DOF） |
| 法线贴图成本高 | 中 | 只给角色和 3–5 个关键道具做 |
| 长时间运行显存泄漏 | 中 | 资源池 + 每日重启兜底 |
| 团队 Three/TS 经验 | 中 | 先做 spike，不直接铺量 |
